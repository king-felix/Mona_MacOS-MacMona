# MidnightMona.png as the app icon

**Date:** 2026-11-14 · **Owner request:** "package MidnightMona.png as the logo of
the app. Use it for the icon and ico of the app, and anywhere else where the
logo may be called for." · **Build:** 134, `Mona-0.1.0-macOS-arm64-local.pkg`

## One asset, every surface

`packaging/macos/resources/MidnightMona.png` is now the single source of truth:
the owner's 1254 × 1254 8-bit RGBA artwork (transparent margin, rounded
indigo/violet mark). It was moved out of the repository root into the packaging
resources, where the build looks for it.

Everything below is a **resample of those exact bytes** — nothing is redrawn:

- **`Mona.icns`** — the macOS bundle icon. Ten iconset sizes from the 1024
  master via `iconutil`, referenced by `CFBundleIconFile`; this is what Finder,
  About, the Dock, and ⌘-Tab draw.
- **`Mona.ico`** — the same mark as a Windows icon container: seven PNG entries
  (16/24/32/48/64/128/256), shipped in `Contents/Resources` and recorded in the
  component manifest as an `image` component. macOS never reads an `.ico`; it
  exists because the owner asked for both formats.
- **Installer art** — `background.png` is now a gradient taken from the logo's
  own darkest painted pixel (top ≈ `#090727`, bottom ≈ `#150E51`), with the mark
  composited bottom-right, clear of the readme text column.
- **In-app brand mark** — the rail's `◐` glyph is replaced by the artwork at
  24 px (`src/renderer/assets/mona-mark.png`, generated by `npm run icon:render`),
  in both the product shell and the design harness. It is `alt=""` +
  `aria-hidden`, as the glyph was: the adjacent word "Mona" carries the name.
- **Window favicon** — `index.html` points at the same mark.

`src/renderer/index.html`'s CSP is `img-src 'self' data:`, so a bundled
same-origin asset needs no policy change; `assetsInlineLimit: 0` keeps the mark
a file rather than an inline blob.

## How the build stays honest

`packaging/macos/icon.mjs` was replaced. It used to synthesise a rounded square
and a gold M from math; now it decodes the committed master and derives
everything from it:

- `readLogo()` **fails the build** if the master is not square, not 8-bit RGBA,
  interlaced, or smaller than 1024 px — a wrong asset must stop packaging, never
  produce a subtly wrong icon.
- `resampleLogo()` averages colour in **premultiplied** form, so the transparent
  margin cannot darken edge pixels into a grey fringe.
- `encodeIco()` writes a Vista-era container of PNG entries; 256 is encoded as 0
  in the directory, per the format.
- `renderInstallerBackground()` derives its gradient from a *painted* pixel — the
  artwork's corner is fully transparent, so sampling (8,8) would have produced a
  black background. That was caught while building this change and fixed by
  scanning for the darkest pixel with `alpha ≥ 250`.

## Verification

- **New tests:** `test/app-icon.test.ts`, 11 cases — the master's shape and
  alpha, refusal of non-square/too-small/16-bit/interlaced input, premultiplied
  resampling, the ICO directory layout (reserved/type/count, 256→0, PNG payload
  at each declared offset), the `.icns` magic and length field with an `ic10`
  1024 element, and the installer art's dark text column plus its chromatic mark
  region.
- **Full suite:** 994 tests in 91 files.
- **Static gates:** typecheck clean, lint 0 errors (3 pre-existing warnings),
  formatting clean.
- **Real shell, 127/127 checks**, run with the capture directory redirected to a
  temporary folder so the repository's pinned product captures were **not**
  rewritten: `p07-shell-home.png` from that run shows the new mark beside "Mona"
  in the rail.
- **Package build (build 134):** every gate through package construction passed
  — payload expansion (669 files, 14 links), the three native components, ad-hoc
  signing of 17 Mach-O files, installer construction and metadata verification
  (`com.mona.workbench.pkg`, 0.1.0, build 134, arm64, macOS 14.0+). The payload's
  `Mona.icns` is byte-identical (`sha256 ce7bec9d…`) to the generated one, and
  `component-manifest.json` records both images. It stopped at the known
  admin-gated `installed_copy`, unchanged from EXT-INSTALL.
- **Icon sizes:** rendered the 16, 32, 512 and 1024 rungs and looked at them; the
  mark stays recognisable at 16 px.

## One assertion had to be generalised, not deleted

The shell smoke's `focus_mode_composer_usable` (P14) asserted that Focus Mode's
sticky `.control-strip` does not cover the Send button. R05 removed that strip
from the focused layout, so the check measured a zero-height element and failed.
It now asserts the same intent in the layout that exists: the topmost element at
the Send button's centre must be the button itself, the button must be inside the
viewport, **and** — where a control strip is present — it still must not cover
it. The original overlap test still runs wherever the strip exists.

## Not verified here

- The installer's own background rendering inside the Installer window, and the
  Dock tile appearance after launch: both need the package installed and an
  interactive session. The user is being handed the `.pkg` for that look.
- `smoke:shell`'s 36 pinned product captures were deliberately not regenerated.
  They were already stale from R04/R05 and R12 owns that reconciliation; this
  change makes the rail logo visible in them, which R12 will pick up.
