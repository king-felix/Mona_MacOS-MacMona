## R11 — performance, accessibility and visual regression (2026-11-14)

- **The console is bounded by measurement.** `virtual-window.ts` (pure arithmetic) +
  `timeline-window.ts` (ResizeObserver + coalesced scroll) + a memoized projection and
  memoized cards. On a real 10,203-event conversation with **601 cards loaded**, 10–16
  nodes mount and a 69,273 px spacer accounts for the rest. Keystroke p95 **16.9 ms**,
  scroll p95 **18.1 ms** — inside two 60 Hz frames. A pane with no height renders every
  card, so a host without layout cannot hide content behind a guessed viewport.
- **Startup and idle meet their budgets.** Interactive in **1.28 s cold / 1.26 s warm**
  (targets 5 s / 2 s). Idle **0.05 % average CPU** over 60 s (target < 1 %).
- **Memory does not, and the exception is derived, not asserted.** 568.7 MiB peak
  against a 350 MiB target; bare Electron 45.3.0 with a blank page measures **356 MiB**
  on this host, so `scripts/r11-smoke.mjs` attaches an exception naming only
  `idle_memory_under_350_mb` and reporting Mona's own share (212.7 MiB) as a
  difference. A run that writes no report, or exits non-zero, fails its own check —
  the first harness version printed `"passed"` for a killed cold run.
- **Accessibility: four real defects, all found by auditing all nine screens.**
  A dialog lost the caret on every parent render (effect keyed on an inline `onClose`)
  and focused its Close button; a modal did not block the window accelerators (⌘1–⌘9

  `<textarea>`, which ARIA prohibits; and the command detail panel was a live region
  duplicating `aria-activedescendant`. Also fixed: two `heading-order` and two
  `scrollable-region-focusable` violations. Final: **9 screens, 0 violations**.
- **Reduced motion and 200 % scale measured, not assumed.** The product had been
  pinning `data-reduced-motion="false"`; that is gone and the media query is the
  mechanism. Under Chromium's own emulation: media query matches, **0** animations,
  pulse collapsed to `1e-06s`. At 200 %: no horizontal overflow, console intact.
- **Three visual regressions fixed from the captures:** a transparent fixed title bar
  with content bleeding through it; "Jump to latest" landing 59 px short and un-arming
  itself; and the composer-below-the-fold layout, which is a *fact* of a scrolling
  document and is now reported with the guarantee that scrolled-to it is fully visible
  and uncovered. A measured `maxHeight` clamp on the console was **tried and

## R09 — slim usage HUD (2026-11-14)

- **Three labelled scopes** on every snapshot: the active turn, the current
  conversation, and the project. `summarizeUsageScoped` narrows the same
  aggregate query; the project scope adds the cost residual so the HUD and the
  Cost screen cannot disagree, while narrower scopes never carry it.
- **Five states, none of them `$0.00` for "unknown":** waiting, empty, unpriced,
  partial (with a lower-bound label and a count of unpriced turns), complete.
- **Cached input is subtracted only when the native count is inclusive;** mixed
  or unknown semantics refuse the subtraction and say so.
- **No polling.** The HUD is a projection computed during `snapshot()`; tokens
  appear when the engine receipts them. Provenance, budgets, model, permission
  and connection state live behind one disclosure so the strip stays small.
- **Verified:** 13 usage tests (including replayed receipts, imported unassigned
  history and Cost-screen agreement), full suite 1,089 in 98 files, shell smoke
  137/137 with four new checks, `p-r09-usage.png`.

## R08 — follow-ups, qualified steering, current activity (2026-11-14)

- **Schema v13 `follow_ups`** stores a queued follow-up with the conversation it
  was written for (`thread_id` + `engine_thread_id`), captured once and never
  re-derived. `queued → dispatching` is one compare-and-set statement, so two
  dispatchers cannot both win.
- **One dispatch boundary: the end of a turn.** `transmit()` is shared with the
  composer, so acceptance, reconciliation and activation cannot diverge. A
  paused queue and a budget stop both leave the row queued with the reason; a
  replaced conversation settles it `stale` with both ids; an uncertain send is
  reconciled once and never resent; a restart keeps rows queued and sends
  nothing.
- **Steering is absent, and says so.** The pinned engine exposes no steer route,
  so the snapshot carries `available: false`, the missing route, and the
  supported after-turn alternative. No steer control is rendered and the smoke
  asserts that.
- **Activity strip** derives from stored frames only: frames span, last event
  age, tool rows keyed by `item_id` with measured durations, Needs-you from the
  engine's pending list, and `unknown` on a failed connection. No timer, no
  narration, no inference.
- **Verified:** 9 queue tests + 8 activity tests; full suite 1,057 in 95 files;
  typecheck/lint/format clean; shell smoke 133/133 with six new checks and
  `p-r08-activity.png`.
- **Not verified:** a live engine turn carrying a dispatched follow-up (needs
  inference), and live steering (no route). Both are stated in the evidence.
